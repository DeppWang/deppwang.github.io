Codex 我最喜欢的两个功能

发表于 2026-10-31 | 更新于 2026-10-31 | | 阅读次数

平时我主要用 Codex 写代码，最近也越来越多地用它写文章、整理想法。用下来，我最喜欢两个功能：实时语音对话，以及 Chrome 里的 ChatGPT 浏览器扩展。

一个方便我把想法说清楚，另一个帮我省掉浏览器里繁琐的手动操作。

先简单说一下这几个名字。ChatGPT 是 OpenAI 推出的 AI 助手，有网页版和 App 版。Codex 则更偏向处理工作任务和写代码。

Codex 有 CLI 版本和 App 版本。App 版本集成在 ChatGPT App 里，CLI 版本是在电脑终端里使用的。

先说实时语音对话。Codex App 里也有实时语音对话，平时习惯用 App 的朋友，可以直接在 App 里使用。

只是我自己更喜欢用 CLI。我现在用的入口，是在 Codex CLI 中输入 /voice，进入语音对话。

对我来说，它最大的好处是可以连续聊，不用把每一句话都手动敲出来。脑子里有什么想法，就先跟它说，没说清楚的地方再补充，也可以随时纠正前面说的内容。

比如写这篇文章，我就是先跟它聊，告诉它我想写哪两个功能，为什么觉得方便，自己会在哪些场景下用。把核心的点说完，再让它参考我最近几篇文章的风格，整理一版出来。看完以后，有哪里不合适，再接着说，让它修改。

这样写文章，对我来说要快一些。想法不需要一开始就整理得很完整，可以先说出来，在对话里慢慢理清楚，最后再整理成文章。

做项目时也是一样。

一个项目往往有很多背景信息。有些是以前做过的尝试，有些是当前的限制，还有些是我为什么想这样做。如果都靠打字，我很容易觉得麻烦，只写下眼前要它做的事情，把这些背景省掉了。

但这些被省掉的东西，可能恰好是 AI 理解我想法需要的信息。

换成说话，输入的门槛低了，我就更愿意把自己知道的东西都告诉它。哪里有前因后果，哪里有自己的考虑，都可以多讲一点。再让它把这些内容整理成项目文档，后面做事时，就有背景可以参考。

App 里原来也可以进行语音对话。不过，我平时用客户端比较少，更多时候还是在终端里做事。现在能在自己常用的 CLI 里直接聊，就方便了很多。

另一个是 Chrome 里的 ChatGPT 浏览器扩展。

我平时也会让 Codex 帮忙操作浏览器，把要做的事情通过语音或者文字在 CLI 里交代给它，再让它去页面里完成。

比如我的 Gmail 邮箱里，订阅和推广邮件比较多，重要的邮件容易被淹没。以前要自己一封封看，再找到退订入口，挺麻烦的。现在可以让它帮我查看，把我不需要的那类邮件退订掉。

还有一些英文邮件，我想知道里面讲了什么，或者找某一条具体的信息，也可以让它去查找、阅读，再把我关心的内容告诉我，不用自己一封封翻。

再比如上传视频，也可以让它帮忙打开上传页面、选择视频、填写标题和简介。很多原本需要自己在浏览器里一步步点击、输入的事情，都可以交代给它来做。遇到验证码、权限确认，或者它处理不了的步骤，再由自己接手。

我喜欢这个功能，主要就是因为它省掉了这些繁琐的操作。有些事情本身不难，但要自己找页面、点按钮、填内容，就容易嫌麻烦，一直拖着。现在可以直接把要做的事情告诉它，自己也就更愿意去处理了。

其实，不用浏览器扩展，通过 Codex 本身的 Computer Use 也能操作 Chrome。刚才我就把 ChatGPT 扩展关掉，让它通过桌面控制，在已经打开的抖音页面里搜索「AI」，也成功显示了搜索结果。装上浏览器扩展后，还可以让它读取网页内容，配合完成这些任务。

另外，看到网页里有不懂的内容，也可以打开扩展直接问它。这是一个顺手的小用途。安装和连接方式，可以参考浏览器扩展的官方说明。

对我来说，这两个功能都减少了一些麻烦：语音对话让我更愿意把想法和背景说清楚，浏览器操作则让我更愿意去处理那些原本嫌繁琐的事情。

现在这篇文章，就是先通过对话把想法说出来，再让它整理成文字的。

用下来，我还有一个感想：AI 工具也需要有自己独特、或者做得更好用的功能，用户才会有更充分的理由选择它。

比如对我来说，CLI 里的实时语音对话，让我更容易把想法说清楚；浏览器扩展帮我省掉了不少手动操作。这些都是我愿意继续用它的理由。

所以，大模型公司除了提升模型能力，也需要不断改进产品，把用户日常要用的功能做得更方便。这个行业迭代这么快，用户的选择也多，能不能持续做出让人愿意用的功能，同样会带来很大的竞争压力。
