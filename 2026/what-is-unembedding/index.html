大模型科普系列（二）：什么是解嵌入矩阵

发表于 2026-11-10 | 更新于 2026-11-10 | | 阅读次数

上一篇写了什么是词向量，文字可以通过嵌入表变成一串数字，交给模型计算。这一篇接着写另一头：模型计算完以后，怎么决定接下来输出哪个 token？

这里会用到「解嵌入矩阵」。先简单说，它是一张用来打分的权重表，把模型最后算出来的一个向量，变成词表里每个 token 各自的分数。后面再把分数转成概率，选择下一个 token。

我一开始不太理解，既然嵌入表已经存着每个 token 对应的向量，那模型算出一个向量后，反过来找到对应的文字不就行了吗？为什么还要有解嵌入这一步？

要弄清楚这个问题，得先看交给解嵌入矩阵的向量，到底是什么。

比如输入「我想喝一杯」，模型要预测后面接什么。为了方便说明，假设最后一个 token 是「杯」。它刚进入模型时，会从嵌入表里查出一个初始向量，这时还没有结合当前这句话的上下文。

接下来，这些向量会经过注意力层、前馈网络等很多层计算。这篇先不展开它们怎么算，只看结果：「杯」这个位置的向量会不断更新，把前面文字中与预测有关的信息融进去。最后用来预测的，是这个位置经过所有中间层处理后的向量。

所以，3Blue1Brown 的讲解里说用最后一个位置的向量预测下一个 token，并不意味着只看最后一个词。位置还是最后那个位置，但向量里的数字已经变了，它包含的信息也不再只有「杯」这个 token。

下面把这个更新后的向量称为「上下文向量」，方便和最初查出来的词向量区分。它不是模型额外生成的另一个东西。

这个上下文向量，不需要恰好等于嵌入表里某个 token 的向量。

可以拿二维空间想象一下。假设嵌入表里只有三个向量，分别在 (1, 0)、(0, 1)、(1, 1)，但二维空间显然不止这三个点。中间层完全可以算出 [2, 3]，它仍然是一个正常的二维向量，只是没有哪个 token 的初始向量恰好等于它。

维度也不需要因为融入了上下文就变多。沿用上一篇的 GPT-3 例子，初始 token 向量是 12,288 维，送到解嵌入这一步的向量也是 12,288 维。中间层改变的是里面的数字。

这时，模型还没有输出几个候选 token，也没有给所有 token 算好分数。它手里只有一个用于预测的向量。解嵌入矩阵接下来做的，就是拿这个向量，给词表里的每个 token 打分。

图：3Blue1Brown，原文。下方黄色框是最后一个位置处理后的向量，黄色箭头把它送去与左侧的解嵌入矩阵相乘；中间得到各 token 的分数，右侧再转成概率。图中的英文候选词来自原作者的例子。

用一个小例子走一遍会更清楚。假设词表只有「茶」「水」「咖啡」三个 token，上下文向量只有两个数字，前面的网络算出了 [2, 3]。下面的数字都只是演示，不是真实模型的权重，也不代表这些中文词实际都会被分成单个 token。

解嵌入矩阵为每个 token 准备了一组输出权重，把它们按行放在一起，就是这样一张表：

候选 token 第一个权重 第二个权重
茶 1 0
水 0 1
咖啡 1 1

现在拿 [2, 3]，分别和每一行做点乘。点乘听起来有点抽象，计算其实就是对应位置的数字相乘，再加起来：

候选 token 计算过程 分数
茶 2 × 1 + 3 × 0 2
水 2 × 0 + 3 × 1 3
咖啡 2 × 1 + 3 × 1 5

同一个上下文向量，分别和三组输出权重计算，就得到了三个分数。 矩阵乘法把这些计算放在一起完成，输入的是 [2, 3]，输出的是 [2, 3, 5]。

每个分数属于哪个 token，由矩阵的行顺序确定。第一行对应「茶」，第一个分数就是「茶」的分数，不需要算完以后再去找这个分数对应什么文字。

这也回答了我前面的疑问：一个向量为什么可以给那么多 token 打分？因为它可以反复参与计算。词表有多少个 token，矩阵就有多少行，每一行算出一个分数。这里并没有要求上下文向量本身对应某个词。

还有一点我之前也有疑问：模型训练完以后，解嵌入矩阵里的权重通常固定了，那不同上下文怎么会算出不同的分数？

还是用同一张表。假设换了一段上下文，前面的网络算出的向量变成了 [4, -1]，这次算出的分数就是：

候选 token 计算过程 分数
茶 4 × 1 + (-1) × 0 4
水 4 × 0 + (-1) × 1 -1
咖啡 4 × 1 + (-1) × 1 3

权重没有变，最高分却从「咖啡」变成了「茶」。原因就是参与计算的上下文向量不同了。

上面两张表把数字直接列出来，是为了看清楚计算。真实模型里的输出权重需要通过训练学出来，前面的网络也在一起训练，让最后得到的向量经过这张矩阵计算后，能给合适的下一个 token 更高的分数。不是随便拿一个向量和一张表相乘，就能预测文字。

也不能把这个过程简单理解成「找离上下文向量最近的词」。两个向量既可以画成空间里的点，也可以画成从原点出发的箭头。点乘算出的分数与它们的方向、长度都有关系，不等于两个点之间的距离。理解这一步，先记住每一行都参与计算、每个 token 都得到一个分数就够了。

接下来才轮到 softmax。前面 [2, 3, 5] 这样的分数，可以大于 1，也可以是负数，还不能直接当概率。softmax 先计算每个分数对应的 e 的次方，再分别除以这些结果的总和，就能得到一组全是正数、加起来等于 1 的概率。

图：3Blue1Brown，原文。左边是分数，右边是转换后的概率，显示为 0.00 的项目是四舍五入的结果，不代表概率严格为零。图中使用的是另一组演示数字。

在这个例子里，三个 token 的概率大约是 4.2%、11.4%、84.4%。同一次预测里，分数越高，经过 softmax 后的概率也越高，排名不会改变。后面的生成步骤再根据概率选择一个 token；如果按概率抽取，就不保证每次都选最高的那个。原始 Transformer 论文第 3.4 节也把最后的线性计算与 softmax 分成了这两步。

选出的 token 加到已有文本后面，模型再继续预测后面的 token，文字就这样逐步生成。

回到真实规模，词表有 50,257 个 token、每个输出权重向量有 12,288 个数字，解嵌入矩阵就有 50,257 × 12,288 = 617,558,016 个权重，约 6.18 亿。它输出的是五万多个分数，不是六亿多个候选。这张矩阵也可能与输入端的嵌入表共享权重，共享时不能把同一组参数重复计数；具体模型怎么安排，这篇先不展开。

现在再看解嵌入矩阵，我觉得最需要分清楚的就是：前面的网络算出一个包含上下文信息的向量，解嵌入用它给整张词表打分，softmax 把分数转成概率，最后再选 token。把这几步分开，就比较容易看清它到底在做什么了。
